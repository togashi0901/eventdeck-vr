# 画面と機能

クラウド上で稼働中の EventDeck VR を実際に操作して取得した各画面と、その機能の説明。

| No. | 画面 | できること |
|---|---|---|
| 01 | ヘルスチェック | `GET /api/v1/healthz` が API・PostgreSQL・Redis の疎通状態を返す。監視から利用する |
| 02 | 公開イベント一覧 | 未ログインでも公開中のイベントを閲覧できる。タイトル検索、プラットフォーム絞り込み、ページングに対応 |
| 03 | イベント詳細 | 開催日時・応募期間・定員・選考方法(抽選/先着)を表示する。ログイン中は自分の応募状況も表示する |
| 04 | 応募フォーム | 主催者が設計した設問に回答して応募する。プロフィール登録済みの項目は自動入力される |
| 05 | マイページ(先着) | 先着方式では応募と同時に当選が確定し、入場用のQRコードと8桁の短縮コードが発行される |
| 06 | 主催者ダッシュボード | 団体のイベント一覧。公開・中止の操作と、設問設計・応募者・抽選・通知・入場・分析への導線 |
| 07 | 応募フォーム設計 | 設問の追加・並び替え・削除。回答形式(テキスト/選択/数値など)と、プロフィールのどの項目を自動入力するかを指定する |
| 08 | 抽選プレビュー | 実行前に対象応募数・当選可能数・優先枠の合致数を確認する。この時点では抽選は行われない |
| 09 | 抽選の実行 | ワンクリックで抽選を実行し、当選・補欠・落選を確定する |
| 10 | 抽選結果の明細 | 全対象者の抽選順位・結果・適用枠を証跡として保存する。乱数シードとあわせて後から結果を再現・検証できる |
| 11 | 応募者一覧 | 応募者と回答内容を一覧表示する。ステータスや表示名・VRChat名で絞り込める |
| 12 | 通知配信 | 当選者または全応募者へ、アプリ内通知・メール・プッシュ通知を一斉配信する。配信履歴も確認できる |
| 13 | 入場管理 | 当日受付。8桁コードまたはQRコードを照合して入場を記録し、入場率を更新する |
| 14 | 入場管理(重複) | 同じコードを再度入力すると拒否される。二重入場はデータベースの一意制約で防止している |
| 15 | イベント分析 | 総応募数・参加率(入場/当選)・初参加率・応募推移を自動集計する |
| 16 | 団体分析 | 団体が主催した全イベントの横断集計と、リピート率(2回以上入場したユニークユーザーの割合) |
| 17 | マイページ(抽選) | 抽選結果が参加者側に反映される。当選者には入場用QRコードが表示される |
| 18 | アプリ内通知 | 抽選結果や繰り上げ当選の通知を一覧表示する。未読の絞り込みと既読化に対応 |
| 19 | メール配信 | 通知ワーカーが非同期で配信した結果メール。開発・デモ環境では Mailpit が受信箱の役割を担う |

これらの画面は `./scripts/demo_stage.sh` を実行すると再現できる
(主催者1名・参加者8名・定員5名の抽選イベントを投入する)。
